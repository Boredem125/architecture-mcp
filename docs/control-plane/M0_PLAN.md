## Decision: security fixes go first in M0 (T0), before any deletion

Security-engineer reported **SEC-01 (critical)**, and I reproduced it on a temp folder with `connector/classify.classify` and the default policy:
- `echo hi && python deploy.py --prod` returns `allow` (the same command alone returns `escalate`);
- `echo hi; rm -rf ./src` returns `allow`;
- `cat .sand*/state/keys/*.seed` returns `allow`.

Cause: the shell allowlist (`policy.py` lines 27-32) is a prefix regex applied with `re.search` (`classify.py` lines 178-182), with no handling of `;`, `&&`, `|`, `$( )`, backticks, redirects or newlines. The `\.sandbox` deny pattern (`policy.py` line 23) is a string regex, so shell globs (`.sandbo?`) beat it.

This breaks the core claim (privileged actions escalate). It outranks the "deletion-only" scope rule, so M0 now starts with T0. It only tightens behaviour. Security and I agree, so there is no dispute to send to the founder; the founder sees it in the M0 summary.

T0 contains:
1. **T0a, compound commands:** allow only if the command has no shell metacharacters (`;`, `&`, `|`, backtick, `$(`, `>`, `<`, newline), or if a real parse splits it and every segment is allowlisted. Otherwise use the shell trigger (escalate).
2. **T0b, protected paths:** check `.sandbox` and `.git/hooks` on resolved paths (glob-expanded, case-folded, via `fs/containment.py`), not by regex on the command string. This applies to shell, Read and Write.
3. **T0c, key files:** a non-removable read-deny on `.sandbox/state/keys/**` (and the future `state/device/**`). The agent's `Read` tool can read them today (`classify._classify_read` allows any read inside the folder). See ADR 0001, security item 4.
4. **T0d (security rated it M0), MCP and config findings from the inventory:** the `mcp__sandbox_` prefix (single underscore) is always allowed in `classify.py:120`, `hook_eval.py:452` and `context_rules.py:61`, so any third-party server named `sandbox_*` skips the allowlist, governance and context rules. Also, `.mcp.json` and `.claude/settings*.json` are not in `_PROTECT_WRITE_GLOBS` (`policy.py:22`), so the agent may rewrite its own MCP and hook config. Security confirmed both through `hook_eval.pre_tool_use`: `mcp__sandbox_evil__send_money` passes with no decision, while `mcp__stripe__create_refund` is stopped. Writes to `.claude/settings.local.json`, `.claude/settings.json` and `.mcp.json` pass too, which lets the agent set `disableAllHooks` or add an unvetted MCP server, so enforcement is gone from the next session on. Fix: match the exact prefix `mcp__sandbox__` only, and add those three paths to `_PROTECT_WRITE_GLOBS` (the `.codex`/`.cursor` configs follow with ADR 0006).
5. **T0e, SEC-02 (high, same root cause): the agent can approve its own requests.** `echo ok && sandbox approve ID --reviewer alice && sandbox approve ID --reviewer bob` passes the hook (bare `sandbox approve ID` is not denied either: it escalates to the human queue; QA's tests require deny), and so does `echo ok && sandbox policy approve-change X --reviewer bob`. This defeats dual control and policy change control. Fix: a non-removable rule that denies any shell segment calling the approver CLI (`approve`, `deny`, `watch`, `grant`, `policy approve-change`, `serve`), whatever comes before it in the chain.

**QA status (17 Oct):** the T0 tests are drafted in `tests/security/test_t0_hotfix.py` (not committed); see `REVIEW_QA.md` sections 7-8. No existing connector test encodes the bugs, so none needs a security sign-off. `test_classify.py::test_shell_arbitrary_escalates` constrains the fix: pipes must escalate, not be denied. Frozen T0 gate (crash test deselected): 701 passed, 0 failed, 1 skipped (539 + 162 new). Post-M0 frozen total: 673 collected, 672 passed, 1 skipped.
