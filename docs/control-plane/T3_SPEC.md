## 3. Server behaviour

**3.1 CSRF (threat 48, A9 item 12).** `rbac.py::rbac_route` attaches a dependency to POST and DELETE routes whose role is `session`, `admin` or `signer_or_session`. When the request carries `__Host-agg_session`, it compares `X-CSRF-Token` with `csrf_token_for(<token from cookie>)` (`auth.py:116`, stateless HMAC) by `hmac.compare_digest` and raises 403 `csrf_missing` / `csrf_invalid`. Dependencies run before body validation, so `json={}` gets 403, not 422 (a malformed JSON body still gets 422 first; outside the catalog). Bearer skip (security M-1, ADR 0001 A9 addendum item 4): one shared predicate decides "authenticated by Bearer" (`Authorization` starts with `Bearer `, as `escalations.py:195/237`), used by the dependency and the handlers; the dependency skips CSRF only when the route's role is `signer_or_session` and that predicate is true. On `session` and `admin` routes CSRF is checked whenever the cookie is present, with or without an `Authorization` header. Cookie parsing is one helper shared with `validate_session`; PUT and PATCH are covered too; errors are `{"error": "csrf_missing"|"csrf_invalid"}`. No cookie: the handler's 401 stands. Bearer on a `signer_or_session` route: the handler uses the Bearer path only and never falls back to the cookie (as `escalations.py:239-260`). Handlers keep their own checks. `logout` is registered without `rbac_route` and already returns 403. Every new route uses `rbac_route` and names its id `{proposal_id}`.

**3.2 Fresh-session rule (S6).** Fresh means `now - web_sessions.created_at <= 900 s` (`SESSION_MAX_AGE`, `enroll.py:37`), `now` from the app clock (`agg_cp.clock`, injectable), as `operator_read_code` does at `enroll.py:368-381`. Older: 401 `reauth_required`. A missing or unreadable session row is refused with 401 (M-7; unlike `operator_read_code`, which skips the check when the row is missing). The tests seed `created_at = last_seen_at = now - 20 min` with a 12 h expiry; the 30 min idle limit (`auth.py:60`) does not trip, so only this rule refuses. Applies to code issue, revoke and publish (stop in T11); not to proposal or approval. Order: CSRF dependency, session (401), fresh (401), role (403), then path id and body, so `publish` with id `fake-id` and `revoke` of a random device give 401. Move one helper into `auth.py`. For a Bearer signer token (S-1, A9 addendum item 1f), fresh means the token row's `created_at` within 900 s; this proves key possession, not a recent IdP login.

**3.3 Enrollment codes (D3, threat 39).** `POST /admin/enrollment-codes` and `POST /admin/devices/revoke`: auth before `await request.json()`; CSRF; fresh; `admin_audit` row in the same transaction (`enrollment_code.issue` with `code_id`, `project_id`, `operator_user_id`; `device.revoke` with `device_id`). Fix the issue response `expires_at` (today it returns the current time). `GET /enrollment-codes/{code_id}`: `Cache-Control: no-store` on every response (200, 401, 404); `enrollment_code.read` row with `code_id` only, in the UPDATE's transaction. No audit payload ever holds the code or `code_hash`. Admin role check (S-3, A9 addendum item 3): code issue needs org admin or admin of `project_id` via one shared helper with `api.py::_is_project_admin`'s SQL, else 403 `forbidden`, nothing inserted; `operator_user_id` not an active org user is 404 `operator_not_found`; revoke needs org admin or admin of the device's project, else 403, `revoked_at` unchanged. Code issue becomes `signer_or_session` (S-1); revoke stays `admin`, session only.

**3.4 Proposals.** New module `ee/src/agg_cp/sync/proposals.py` (router registered in `app.py`). `POST /api/v1/admin/bundle-proposals`: CSRF, auth (session, or a signer token meeting S-1 conditions, A9 addendum item 1), org admin or admin of the project through the shared helper (403); `admin_audit` rows record `auth` and, for a token, `key_id`. Raw body above `BUNDLE_MAX_BYTES + 64 KiB` is 413; body parsed with a duplicate-key hook and `parse_constant` refusing `NaN`, `Infinity`, `-Infinity`; body keys exactly `{project_id, bundle}` or `{project_id, bundle_raw}` (a string parsed the same way); the bundle a JSON object. Bundle keys: `change_approvals` in any form is 400 `change_approvals_refused`; a key outside `BUNDLE_FIELDS` is 400 `unknown_fields`; a server-owned key (`org_id`, `project_id`, `sequence`, `base_sequence`, `registry_version`, `environment`, `issued_at`, `not_before`, `expires_at`) is 400 `server_owned_field`; each of the four policy sections present must be an object. Project in org, else uniform 404. The server fixes: `base_sequence` = max stored `sequence` of any label for the project, else 0; `sequence` = base + 1; `registry_version` = `Registry.version` from `verify_chain` over `get_chain` (fingerprint from the stored genesis, as `registry.py:89-95`), 0 with no chain; `environment` = `projects.environment`; `issued_at` = `not_before` = proposal time as int epoch seconds; no `expires_at`. Canonical bytes via `_canonical_json_bytes`; above `BUNDLE_MAX_BYTES` is 400 `too_large`; hash `_bundle_hash`. Base payload = the stored row at `base_sequence` or `DENY_ALL_BASE`, a module constant copied from the connector's step 10 literal (`bundles.py:545-550`; T4 pins it with `ast`). `diff` = per section of (`folder_policy`, `governance_policy`, `mcp_policy`, `approval`, `environment`) that differs, `{"old", "new"}`; `loosened` = connector `loosened(base, payload)`. Insert the request row and `admin_audit` `bundle_proposal.create` (id, project, hash, base) in one transaction. 201 `{id, bundle_hash, bundle, base_sequence, sequence, registry_version, diff, loosened, status}`; every refusal 400 and nothing stored. `GET .../bundle-proposals?project=` (cursor bound to org, T1 style) and `GET .../bundle-proposals/{proposal_id}`: org members or a confirmed signer token of the org; uniform 404; the detail adds the stored approvals (user, key id, kind) and `base: {envelope, change_approvals}` for base >= 1 (the server's word; the CLI verifies it).

**3.5 Approval.** `POST .../bundle-proposals/{proposal_id}/approvals`, role `signer_or_session` (as `escalations.py:228-280`: confirmed scope only, device token 403), any org user. Order: (1) body exactly `{"approval": env}`, `env` exactly `{kind, sig_v, payload, signatures}`, kind `agg/policy-change/v1`, `sig_v` 1, exactly one signature `{key_id, alg: "ed25519", sig}`: else 400 `bad_approval` / `exactly_one_signature`. (2) Proposal in org and `open` (404, 409 `not_open`); `payload == {"bundle_hash": <proposal hash>}` else 400 `hash_mismatch`. (3) Refusals from the projection, allowed by ADR 0010 s8: `approver_keys` row by `key_id` absent or kind not `cli` is 400 `wrong_kind`; owner (via `cli_key_lookup`, which covers pending signer links) equal to the proposer is 400 `proposer_cannot_approve`; owner not the authenticated user, or (token caller) `key_id` not the token's bound key, is 403 `not_key_owner` (lead, refuse-only; S-1 condition c); the user already approved is 409 `already_approved`. (4) `base_sequence` != max stored sequence is 400 `stale_base`. (5) Registry from the chain; none is 400 `no_registry`; entry missing is 400 `not_in_registry`; recheck proposer and owner against the entry's `user_id`. (6) `_verify_change_approvals(payload, [env], registry, is_loosening=False, is_first_bundle=False)`; `BundleError` is 400 `approval_invalid`. (7) Insert `policy_change_approvals` (`change_request_id` = proposal id, `user_id` from the registry entry, `key_id`, canonical envelope, `signed_at` now) and `admin_audit` `bundle_proposal.approve` in one transaction, under `SELECT ... FOR UPDATE` on the request row.

**3.6 Publish (T3 shell).** `POST .../{proposal_id}/publish`, `signer_or_session`, admin, fresh. Path id taken as `str`; non-UUID or foreign is 404 after auth. Lock the row; not open is 409; stale base is 400 `stale_base`; a stored approval whose `user_id` is the publisher is 400 `publisher_in_approvals`, the proposer 400 `proposer_in_approvals`; otherwise 400 `verification_pending` until T4. Each refusal calls `conn.rollback()` first (M-2, T3-F2), then writes `admin_audit` `bundle_proposal.publish_refused` (reason, `auth`, token `key_id`) in its own transaction; nothing in the policy tables, and no T3 path returns 2xx (M-9).

## 4. CLI: new `src/sandbox/cli/change_cmds.py`, attached from `main.py`

`register(cli)` adds `issue-code`, `propose-bundle`, `approve-change`, `publish` to `cli.commands["signer"]`; `sync_cmds.py` (connector TCB) is imported, never edited. The agent cannot run them: `signer` is in `classify._APPROVER_SUBCOMMANDS`. HTTP only through `with httpx.Client(follow_redirects=False, timeout=30) as c:` and `c.get` / `c.post(url, json=...)` (the tests patch `httpx.Client`); `_check_transport_safety` first; any 3xx refused; status checked by the command, never `raise_for_status`; refusals exit 1 printing the server's `error` and `detail`. Server strings printed via `json.dumps(..., ensure_ascii=True)` or `_check_display_safety`. Credential: a signer token minted over httpx with the `agg/signer-assert/v1` assertion from `--key-file` or the linked key; with no key configured the request is sent without one and the server's 401 is shown; with a key whose token fetch fails, the command refuses. A new token per command, never written to disk; no new key loader (M-13). Admin routes accept it under S-1 (A9 addendum item 1).
- `issue-code --server --project --operator`: posts `{project_id, operator_user_id}`; prints `code_id`, expiry and "the operator reads the code once at /enroll/<code_id>". Never writes anything to disk. Conflict F-2.
- `propose-bundle --server --project --bundle-file`: strict local parse; posts `{project_id, bundle}`; requires `bundle` in the response, recomputes `_bundle_hash(bundle)`, checks its four policy sections equal what it sent and its other keys are server-owned; prints `proposal <id> bundle_hash <h>` only then; else exit 1 naming the server's hash and the mismatch.
- `approve-change <id> --server --key-file --expect-fingerprint --yes`: first resolve the trust anchor locally, before any network call (S-2, M-10, A9 addendum item 2): (a) an enrolled workspace's `load_verified_state` after `_refresh_registry_chain`; (b) `--expect-fingerprint`; (c) stored `<key_home>/signer/root_fingerprint`; then `verify_chain` over `GET /api/v1/sync/signer/registry`. None of the three: exit 1 via `click.ClickException` (not `required=True`). Never writes the fingerprint file. Then mint the token and GET the detail; refuse unless `_bundle_hash(bundle) == bundle_hash`, keys within `BUNDLE_FIELDS`, no `change_approvals`, `sequence == base_sequence + 1`. Base 0: base = the CLI's `DENY_ALL_BASE` copy (needs its own `ast` pin, QA-4). Base >= 1: with the verified registry, verify `detail.base.envelope` with `_verify_envelope_structure`, `_verify_signature(env, _bundle_signer_pub(registry))`, `_verify_bundle_signer_in_registry`, its `sequence == base_sequence` and org and project equal the proposal's, else refuse. Then print the diff computed from those bytes, the `loosened` result and the approvals needed (2 for base 0 or a loosening, else 1); never print the server's `diff`. Then, against the verified registry, refuse if the proposal's org differs, if `registry_version` < `Registry.version`, or if the own key is not a `cli` entry with a counting role. Confirm unless `--yes`; sign `canonical_bytes("agg/policy-change/v1", {"bundle_hash": h})` with exactly one signature; post `{"approval": env}`. No POST to `/approvals` before every local check passes. Named limit (S-2): with no workspace there is no high-water mark, so these registry checks are advisory; the connector's step 8 stays authoritative.
- `publish <id> --server`: posts `{}`; prints sequence and hash on 2xx, else the refusal and exit 1.
