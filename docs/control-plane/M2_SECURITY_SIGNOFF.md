## Gate observation (functional, fails closed; not a vulnerability)

The M2 connector sync path has no product entry point. There is no `sandbox enroll`/`sync`/`signer` CLI command (`src/sandbox/cli/`). Nothing calls `run_once` or `apply_external`. `_fetch_decisions` (`process.py:350-372`) drops the decisions. `_upload_escalations` reads `.sandbox/pending/`, which the hook never writes (it writes `escalations/pending`). In `ee/web`, `App.tsx` has no inbox, and `approval.ts:89` signs with a fresh key each time, not the IndexedDB key. Today a managed laptop simply never gets a remote approval (fail closed). But demo steps 3, 5 and 11 cannot pass without this wiring. The wiring must land with H1-H3 and M2 fixed, and it needs its own security review.

## Verified clean (cross-task)

- **Agent writes to sync state (threats 20, 26, 37):** every M2 state file is under `.sandbox/` (`state/sync/{managed,pinned_root,registry,bundle,server_time_state,seen_nonces}.json`, `policy_history/`, `pending/`, `claimed/`, `done/`) or the key home (managed marker copy, device key). Both are covered by the non-removable `_PROTECTED_SEQS` and `keyhome.touches` checks in `classify.py:52`, `:373-382` for Write/Edit and the shell forms. `enroll`, `unenroll`, `sync` and `signer` are in `_APPROVER_SUBCOMMANDS` (`classify.py:64-67`).
- **Server tenancy:** every M2 SECURITY DEFINER function (0007-0010) has `SET search_path = pg_catalog, pg_temp`, REVOKE PUBLIC and GRANT agg_app. M2 tables are FORCE RLS (0007:388). The decisions route is scoped to the token's `connector_id`. The approvals route has T13 three-way identity binding.
- **Deny path:** one valid signed deny is honoured under skew, registry expiry and nonce corruption (fail toward deny). Prod remote approvals are refused on both sides (N9).
- **Scanners:** Semgrep 1.178.0 (`.venv`, `p/python` + `p/secrets`) on `approval.py`, `sync/`, `ee/src/agg_cp/sync/` and the new test: 0 findings. gitleaks 8.30.1 on `9b0d1b0..HEAD` (42 commits): no leaks. Trivy (vuln + misconfig, HIGH/CRITICAL) on `ee/`: 0.

## Stated limits

This is a code review, not a penetration test or a certification. Same-user code outside the hook can read the key home and write `.sandbox/` (ADR 0007). The server can forge non-prod browser-key approvals (S1, M2_BASELINE 5b). L3 above.

## Verdict

**CHANGES.** H1, H2 and H3 break guarded properties: dual control by two humans for THIS action, hand edits cannot loosen policy, and the TCB state stays intact. Accepting any of them as a limit needs the founder. Fix H1-H3, M1 and M2 before the sync wiring and the T16 demo, remove the xfail markers in the same change, then run security round 2 on that diff. M3 and M4 should land with the wiring. L1 and L2 can follow.
