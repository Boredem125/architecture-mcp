Jailed Agent Sandbox Architecture

Milestone 1: Real CLI launcher with privilege broker, live streaming, and comprehensive logging

Trusted Key Components

  • FastAPI Server: Entry point for launch requests and WebSocket subscriptions
  • AppLauncher: Resolves app type, creates jail, spawns process with Job Object, streams output
  • EventBroadcaster: Real-time WebSocket to frontend showing live process output and broker events
  • PrivilegeBroker: Human-in-the-loop gate for elevated commands—never runs untrusted code
  • SessionRecorder: Immutable audit trail (logs.txt, modified.txt, .trash/) per jail session

Jailed Isolation Model

  • Win32 Job Object: Resource limits (memory, CPU, process count). Kill-on-close ensures cleanup.
  • NTFS ACL Jail: Filesystem boundary. Process can only touch its jail directory.
  • PATH Shims: powershell.cmd, pwsh.cmd, cmd.cmd intercept elevated requests and route to broker.
  • Demo Agent Fallback: If CLI not installed, runs real jailed Python process—sandbox still demonstrable.
  • Monitored vs. Enforced: Enforced mode uses dedicated user + ACLs; monitored mode logs out-of-jail attempts.
Broker / Trusted: Server-side gates and decision points
Jailed: Untrusted process sandbox with resource limits
Escalation: Privileged request flowing to broker
Approved: Broker-approved result flowing back to process
